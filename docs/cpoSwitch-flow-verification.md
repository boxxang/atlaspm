# CPO Network Switch System — flow verification

The `cpoSwitch` built-in template was restructured around four dies and two
packages: the Switch SoC, the I/O die, the electrical IC (EIC) and the
photonic IC (PIC), plus the optical engine (OE) package — the EIC stacked on
the PIC, with its engine substrate and fiber — and the main package, which
carries the Switch SoC, the I/O die and known-good OEs. This report checks
that the result reads as a real program, not just that the unit tests pass.

The tables in the appendix are generated by `npx tsx tools/cpoFlow/report.ts`
from the template itself. The baseline is
`tests/unit/fixtures/cpoSwitchBaseline.json`, a snapshot of commit `74ef9a8`
taken before any edit. The findings and judgements below are written by hand.
The checks that code can decide are unit tests: `describe('CPO program flow')`
in `tests/unit/cpoSwitch.test.ts`.

### Why these weeks

The intended critical path is PIC → OE stack → KG-OE → main package first
build, and the weeks are set so that it is the critical path:

- **The OE stack design freezes at W66, before EIC and PIC layout starts.**
  ICD-04 owns the bond pad map. OESD-01 turns it into the physical bond
  interface. The freeze (OESD-07) fixes the pad geometry, the coupler
  placement and the keep-outs, and then IMPL-04/05 draw both dies once. The
  cross-die signoff (SGNO-12) checks the finished layouts against the freeze
  before wave 1.
- **PIC and EIC tape out six weeks before the Switch SoC and I/O die** (W98
  against W104). The photonic fab and its post-fab processing take 18 weeks
  (15 + 3), and the OE build follows them.
- **The optical path runs:** PIC fab out W117 → bumping, through-oxide-via
  reveal and bond-surface prep W117–120 → PIC wafer test W120–125 → EIC/PIC
  KGD release, with dicing and facet prep, W126 → stacking W126–130 → engine
  substrate W129–132 → fiber attach W131–135 → engine test with stress screen
  W133–138 → KG-OE review W138–140 → OE mounting W140–143 → package test
  W143–148.
- **The Switch SoC path runs:** fab W108–122 → sort W122–128 → die bank
  W128–132 → die attach W132–138. It finishes two weeks before the OEs are
  ready.
- **Power-on does not wait for the engines.** It starts at W140 on the
  electrical-only build (PKGA-11, ready W138), so the first electrical link
  (W150) is on electrical silicon. Optical bring-up and everything after it
  waits for the full build.

## Critical path and slack (V5)

**Method.** Critical path is computed by dependency logic, by
`cpm()` in `tools/cpoFlow/analysis.ts`:

- Each activity keeps its template length.
- Each dependency keeps the relation the template gives it:
  - **finish-to-start** where the producer finishes first;
  - **finish-to-finish** where the two overlap and the producer finishes first;
  - **start-to-start on an interim output** where the producer outlasts the
    consumer.
- An overlap also keeps the template's lead from the producer's start to
  the consumer's start, because the first lot has to come through one step
  before the next can begin.
- A forward pass gives each activity its earliest start. A backward pass from
  an end activity gives its **total float** against that end; zero float means
  it is on a critical path.

The first version of this model let an overlapping step start the moment
its predecessor finished. That collapsed the serial engine build (stacking,
substrate attach, fiber attach, test — the same units in sequence) to almost
nothing, and showed the program finishing 19 weeks early. The independent
review (V7, #1) caught it. Keeping the lead fixes it: the logic now finishes
at the template's dates, W148 for the first build and W218 for production,
so the template carries no hidden padding on these paths.

**Into the first package build** (PKGA-06), the driving chain is:

| Activity | Wait |
|---|---|
| … ICD-04 → DSGN-05 → IMPL-04 → SGNO-03 → SGNO-09 (wave 1 review) | |
| **OTO-02 PIC tapeout** | FS |
| **WFAB-04 PIC fab → WFAB-08 PIC post-fab** | FS |
| **SORT-04 PIC wafer test → SORT-05 EIC/PIC KGD release** | FS / FF |
| **OEB-02 stacking → OEB-03 → OEB-04 → OEB-05 engine test → OEB-09 KG-OE** | FS / FF |
| **PKGA-04 OE mounting → PKGA-06 package test** | FS |

**Total float**

| Path | Into the first package build | Into production release |
|---|---|---|
| OE: OTO-02 → WFAB-04/08 → SORT-04/05 → OEB-02…09 → PKGA-04 | **0** | **0** |
| Switch SoC: WFAB-01 → SORT-01 → SORT-07 → PKGA-03 | **2 weeks** | 0, through the first electrical link |
| I/O die: MTO-02 → WFAB-02 → SORT-02 | **4 weeks** | 2 weeks |

Unit tests check this. The test "sets the first package build by the photonic
IC and optical engine path" asserts:

- the OE path has zero float into both PKGA-06 and RAMP-07;
- the Switch SoC and I/O die fab and die attach have positive float into the
  build;
- the chain into PKGA-06 runs through OTO-02, WFAB-04, SORT-04, OEB-02, OEB-09
  and PKGA-04.

**Into production release** (RAMP-07), the OE path is critical, and so is a
second chain:

- **The chain.** It runs from Switch SoC tapeout (MTO-01) through the
  bring-up firmware on the final netlist (PKGA-10) and the bring-up labs
  (PKGA-09). From there it goes through power-on on the electrical-only build
  (PON), anomaly triage and containment (SDBG-01/03), and the NPI builds
  (EVT → golden units → PVT → readiness). It ends at the release review.
- **Why.** Production is gated by the NPI cadence and the production stepping
  as much as by first optics. That is the right reading for a first-of-a-kind
  switch.
- **No change needed.** The template has no padding on that chain either, so
  any slip on it moves production one for one.

**Thin slack.** Two weeks on the Switch SoC path into the first build is
thin. A Switch SoC fab slip of more than two weeks makes the electrical
silicon critical again. The alternative would be to push wave 2 earlier,
into the signoff of a design six weeks less mature. The electrical-only
build (PKGA-11) and the daisy-chain dry run (PKGA-12) protect the schedule:
neither waits on an OE, and power-on starts on PKGA-11.

**Program length:** W262 → W266 (+4). Production release W214 → W218 (+4).

**Work that starts before a gate it follows**

The appendix lists, per gate, the later-stage work that starts before it. All
of it was reviewed. It is intended parallel work, in four kinds:

1. **The lifecycle overlap the template is built on.** Requirements start
   during concept, interfaces during architecture, and design before the
   interface freeze. Each starts on the earlier stage's draft and is revised
   at the gate.
2. **Long-lead work started at risk.** This covers the first-build material
   (PKGA-01, before the signoff gate) and the TINF hardware (before the design
   freeze). It also covers wave 1, which goes before the SGNO gate: OTO starts
   W98, while "All Silicon Ready for Tapeout" closes at W104 on wave 2. Wave 1
   has its own go (SGNO-09, W98), so this is the two-wave design and not a
   bypass. Wave 2 tapes out at W104, exactly when its review (SGNO-10)
   closes.
3. **Pipelined manufacturing.** EIC sort starts before First Silicon (W122)
   because the EIC lots are out at W114. OEB-02 starts at W126, before the
   SORT gate (W132), because its input is the EIC/PIC KGD release (SORT-05).
   The SORT gate is the Switch SoC/I/O die KGD.
4. **Bring-up and debug.** Power-on and the first electrical link (PON,
   W140–150) run on the electrical-only build, before the first package
   build gate (W148) closes on the full build with engines. This is
   deliberate.

None of these early starts is unintended. One is a change in kind: the SORT
gate (Known-Good-Die Ready) is now the Switch SoC and I/O die gate. The EIC
and PIC dies have already gone to OEB by then, and their gate is
Known-Good Optical Engines Ready.
